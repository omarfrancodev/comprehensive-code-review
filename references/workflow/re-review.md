# Incremental re-review

Choose presentation.kind once: review for a new review; rereview when checking previous findings/conditions against current inputs; complement for an explicitly additional bounded area/check of a prior review. Titles are Code Review, Re-review and Complement Code Review respectively, with the functional subject. Both later kinds create a new linked archive; do not overwrite the earlier review or claim its untouched scope was revalidated. Complements preserve applicable IDs and identify the added scope/evidence and remaining limits; they do not automatically inherit or close earlier findings. Re-review ID decisions below apply only to claims actually reassessed.

Before creating another run, query the bounded candidate set and select the exact prior archive as described in [recovery.md](../archive/recovery.md). Use a verified completed report as history only when its freshness is understood; inspect an incomplete run before continuing or restarting it. Use the canonical fully scanned, integrity-verified latest selector for admission under [reuse.md](reuse.md); never choose by raw timestamps, folder order or finding ID. An ordinary review request authorizes a new review when the changes or required context differ or cannot be proven equivalent.

Before preparing a guided follow-up, verify the selected local archive with `artifacts followup-baseline --repo <repo> --scope-file <scope.json> --run-dir <prior-run>`. Supply the same `--logical-scope-input` used for any explicit module, feature or partial-local scope. The read-only command returns the verified review ID and the path and digest of its exact `review.json` for both full and compact archives. Recover the prior base/head/snapshot, IDs, aliases, check references, coverage and pending conditions from that result. If only a note URL or historical prose is available, use it as context for a bounded new review and disclose why continuity cannot be verified. The same applies to an unavailable, incomplete, damaged or unrelated archive.

For a full predecessor and full successor, link the exact prior archive in cierre.json using `--previous-run`. Retain the earlier final record and any optional measurements unchanged. Read only evidence required for the current comparison, not all historical runs or a cross-run context cache. A follow-up's five covered rows do not certify the original ordinary scope. Ordinary admission requires the explicit native ancestry proof described in reuse.md, including the ancestor's complete context outside the follow-up; a linked identity alone is insufficient.

Compare old/new head and base: a moving base can change effective changes even with unchanged head. Map corrected findings, changed/deleted paths, dependencies/interfaces and new risks. Reinspect affected flows and pending required checks; reuse unaffected evidence only with applicable inputs and a recorded reason. Changed execution revision/configuration/fixtures require refreshed checks or explicit justification of unchanged inputs; never relabel old execution as new execution.

Keep IDs for the same cause across renamed files/shifted lines; retain duplicate aliases and genuine historical IDs through identifiers.md. Prior IDs become resolved (proved correction), still_valid (reconfirmed), withdrawn (earlier claim disproved), or not_reevaluated (outside actual follow-up scope or not rechecked). New causes get new canonical IDs. Every prior row retains source review/reference, original finding ID/title, verified public URL if available and supporting check IDs under result-contract.md. Final outcomes are not candidates; never silently delete earlier claims. An unresolved claim remains uncertainty, not a confirmed fix task.

Description-only changes refresh its consistency result against the same code. Corrections can affect adjacent consumers, so do not inspect only the original line. Select for the current follow-up under profiles.md: honor its explicit profile; otherwise reassess eligibility and affected mechanisms/invariants, without blindly inheriting the earlier profile or restarting unaffected flows. A small fix to a deep mechanism still reassesses that mechanism; prior extended does not force a new extended plan when its independent assignments are no longer required.

Finish with exact current scope, findings/uncertainties and concise ID changes. Blocked checks or unknown requirements are not resolved. Freshness, responsibility, report and remote authorization rules still apply.

For each correction, identify the mechanism it adds, changed contracts/defaults, consumers and lifecycle obligations. Reassess state transitions, old persisted data, cleanup and repeated work when those mechanisms are present. Reusing the original finding's passing regression does not establish the correction's adjacent behavior. Preserve a relevant nonblocking finding or uncertainty instead of dropping it because the original blocker was fixed.

A verified compact report may be cited as a prior result, but does not acquire archive-8 recovery or prove equivalence from an absent full inventory. Reassess the actual scope and preserve only facts and identities supported by retained sources.

Before verification, capture each applicable resolution decision from chat, a PR/MR comment or description, or attached documentation. Identify the person with authority and the scope of that decision. A proposed omission, acknowledged risk or pending debt alone does not authorize acceptance. Record an accepted decision, its source and any conditions under the [assessment extension](../contracts/assessment.md). Keep the note's original bytes in the initial input selection. Give the verifier that disposition with the candidate so the verifier can assess risk and required resolution separately.

For an adjacent case, name the existing consumer or obligation and the specific question introduced by the correction. Record the applicable obligation, reachable trigger and demonstrated consequence in the current verification. Keep unrelated findings as `not_reevaluated` and preserve applicable prior IDs and aliases. For unchanged accepted debt, carry the exact decision and its evidence forward. A new check run, reformatted output or moved line alone does not reopen it. Reopening requires a source tied to a current delta observation and a material explanation of what changed.

Select a copy of the verified prior `review.json` as derived assessment evidence. Use the native `--previous-run` link when available. For compact ancestry or a prior compact result, identify the exact prior archive `review.json` in `previous_reviews.reference`. The writer verifies that archive and matches the copied bytes. The copy and new execution proofs are derived evidence rather than material inputs. The retained scope line and delta appear in the response, report and public comment.

When `followup-baseline` offers `legacy_previous` for a chained assessment v2 baseline, use that inventoried file and digest as optional `assessment.previous.legacy_source` in the new v3 result. Select it as derived evidence under a distinct flat filename. This exact copy can distinguish an independently published authorization from a disposition copied to an alias. If the precursor is unavailable, retain the applicable conditions and disclose uncertain attribution with `history_incomplete`.
