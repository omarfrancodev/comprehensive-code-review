# Progressive access and investigation checkpoints

The coordinator embeds relevant steps in briefs. Limits govern expansion, not coverage claims.

1. Obtain change/file summaries and needed MR/PR metadata once. Select affected flows/project gates.
2. Read hunks/containing symbols through bounded searches/ranges. Retrieve check results/errors before full logs. Raw artifacts remain accessible.
3. Follow concrete producers/consumers, registration/configuration and unchanged dependencies until behavior/contracts can be assessed. Each expansion names its unanswered question or required gate.
4. Reuse fragments by exact revision/snapshot, path and range. A small neutral index in context or owned evidence/reads.json can retain source identity, range, artifact reference and actual output size. Independent verifiers still inspect decisive raw code; the index cannot replace judgment.

Set supported per-call output bounds; request subsequent ranges as needed. Truncation is incomplete evidence. Entire listings/files/review histories/logs are not default worker inputs. Explicit full audits/project instructions can require broader coverage.

## Checkpoints

Discovery ends with inspected flows, evidence-backed candidates and gaps. Before dispatch keep candidates with observable triggers, affected requirements/conventions and consequences. Discard style-only/unsupported hypotheses. Unknown baseline yields unknown origin, not rejection. Material questions/independent gates remain eligible without candidates.

Balanced normally uses one discovery pass and one verification batch per scope when required. Economy keeps these phases in one session; deep/extended retain distinct flow owners within their justified assignment limits. P3 code candidates still require balanced verification. Extra investigation records changed inputs/new evidence or an uncompleted gate. Repeating unchanged blocked checks cannot resolve their gap.

Stop when evidence settles a claim or required missing information cannot be obtained with available capabilities. Retain material uncertainty and existing insufficient-evidence verdict rules. Soft checkpoints cannot waive gates, hide findings or claim approval from exhausted budget. Profiles do not configure model effort/token limits.
