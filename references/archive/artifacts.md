# Persistent review archive

## Current archive layout (schema 8, layout 2)

Native runs use `<root>/<repository-group>/<logical-scope-group>/<UTC-created>--<version-hint>--<20-hex-run-id>/`. The repository group keeps its stable repository identity. The scope group describes the stable logical selector, while the run name exposes the exact input revision and unique run identity. For example, two reviews of MR 1010 are grouped under `mr-1010/`; each run is then visible as `20261018T150000Z--head-90e54abb1234--<run-id>`. Dates in paths are UTC and are not added to report content.

`logical_scope` is `{mode, selector, hint, identity}`. Its SHA-256 identity hashes canonical `{mode, selector}`; hints are presentation only. MR/PR selectors use the pinned reference, commit selectors use exact head and base, ranges use symbolic refs or exact commits, modules/features use an explicit reference and relative POSIX boundaries, and local selections use their mode and selected boundaries (`[]` means the whole requested local scope). A module/feature or partial local selection must provide `--logical-scope-input`; selectors cannot be inferred from a title or abbreviated revision. Limits are 64 boundaries, 500 characters per selector string, 64 KiB per selector document, 80 characters per group and 128 characters per run component. Unsafe, ambiguous or colliding hints never replace full identity.

Archive 8 adds `layout_version: 2`, `logical_scope` and its ownership-marker binding; final review schema 10, trace schema 1, packet version 1 and the existing locks, claims, transaction recovery and restart reservation semantics remain in force. Preparation, reserved restart, validation, lookup and delivery must use this same layout contract. An archive predating schema 8/layout 2 is `unsupported_layout` for operational helpers. Preserve it unchanged; do not resume, restart, recover, rename or migrate it through this helper. A verified report may be ported separately into the three-file historical consultation package in [history.md](history.md), which is never a native run.

The coordinator keeps three locations distinct: the user checkout, run-owned execution scratch/workspaces, and the persistent archive. A user development worktree remains user-owned. Native scratch is not the durable destination. Honor no-create requests and existing write permissions; an inaccessible root produces an explicit persistence limitation and an in-conversation record, not a silent switch to project docs or provider scratch.

## Root and run identity

Choose the internal archive root once: explicitly requested internal archive location, otherwise CCR_ARTIFACTS_DIR, otherwise the user's home/.comprehensive-code-review/reviews. `--output` belongs only to explicit full/brief delivery under delivery.md and does not change this root. A project-docs internal archive destination needs an explicit archive-location request; a normal review request does not select it. Keep the default outside the project, temporary sessions and skill installation. Reject links/reparse-point paths; report blocked access instead of modifying permissions or configuration.

Mandatory layout: <root>/<repository-slug>-<stable-id>/<scope-slug>/<timestamp>-<run-id>/. An internal-archive location override selects the root, not a different layout. Use exactly the `run_dir` returned by `prepare`; never rebuild, shorten or rename its components. Historical folders are not precedent for new runs. Multiple MR/PRs get separate runs; re-review creates another run referencing the earlier one, never overwrites it. History persists until explicitly deleted; do not add automated retention or load past context as a cache.

The repository ID is the first 20 hex characters of SHA-256 of the normalized remote identity, or resolved Git common-directory identity for absent/relative local remotes. Scope folders contain mode, reference hint and the first 16 hex characters of SHA-256 of canonical pinned scope JSON. Runs use UTC YYYYMMDDTHHMMSS and a unique 20-hex execution ID. `review_artifacts.py` defines canonical JSON bytes and Windows-safe slug derivation. Schema 3 binds the directory to stored `repository_identity`, `repository_key`, `scope`, `created_at` and `run_id`, so validation does not require the original checkout or an unchanged remote. Schemas 1/2 keep compatible structural checks without migration. Preserve nonconforming historical archives; a failed gate is a reported compatibility limitation, not permission to rename/rewrite history.

If this repository/scope may have a prior or interrupted review, perform the read-only bounded lookup in [recovery.md](recovery.md) before preparing a second run. Lookup never chooses an archive; inspect/continue/restart the exact selected run.

## Bootstrap and temporary evidence

New archive schema 7 preserves `review_id: CR-<run_id>`, mandatory `trazabilidad.jsonl`, processing transitions, profile-selection history, operation disposition, checkpoints, lineage and owned resource claims. Schema 6 introduced once-resolved canonical harness metadata; trace schema 1 remains unchanged. New final schema 10 records bind their profile history and assignments to the archive run. Preserve archive schemas 1–6 and final schemas 1–9 without reconstruction or migration.

Lifecycle state: `prepared → processing → retaining → closing → complete`. Archive-7 operation disposition independently records `open`, `paused`, `blocked`, `superseded` or `complete`. Preparation fixes scope and owns the archive; processing means work has begun, not that an executor is currently alive. The existing `record-event` mutation starts processing on the first observed `agent`, `discovery`, `check` or `grouped-verification` milestone with status `started`, `completed`, `passed`, `failed`, `blocked` or `skipped`. Blocked/skipped reflect an observed attempt or execution decision, never an anticipated impediment. Profile selection, planned/pending assignments, authorization, registration and preparatory validation do not start work. Record `discovery/started` before discovery, or `agent/started` after observing dispatch; reuse an equivalent existing milestone instead of adding a duplicate.

Register resources while prepared or processing, before using them. Retain directly from prepared remains compatible with callers supplying an already-built result; it does not invent earlier activity. New skill executions still record their meaningful start. Schema 4 preserves its previous states; schemas 1–3 do not acquire synthetic traces. A failed/pending transaction prevents a validated state claim and is recovered using its original event bytes. Later checkpoints never regress closing to processing.

Load this reference before creating any artifact. First pin inputs with read-only inspection. Before durable `prepare`, put its required `scope.json` in `evidence/` of an exclusive owned session, with an ownership manifest recording that bootstrap. A writing executor's session uses workspaces.md; a static-only review may use a native owned evidence session without creating a Git worktree. This bounded preparation is the only pre-run artifact phase: pass that session via `prepare --temporary-path`, validate the returned run, and finish registration before discovery, worker dispatch or validation commands.

Once prepared, create descriptions, captures, identity hashes, discussions, context/checks and role packets within that registered session's `evidence/`. Additional owned sessions/executors need `register --temporary-path` before use; planned directories can be registered before creation, and registration repeated after their ownership manifest exists. Do not create a parallel scratch directory beside `reviews/` or elsewhere outside the registered session. Original user inputs can be read where they exist; this rule governs review-created temporaries. Workers write assigned evidence; the coordinator owns durable metadata.

## Mandatory compact records

For pending trace recovery, use an allowed helper mutation on the exact owned run. Before retention, `register` with the current verified resource list recovers the preserved intent; do not clear or replace resource ownership merely to recover. An interrupted retain/close is retried with its original verified inputs and observed cleanup. Read-only validate never repairs. Failed ownership/hash recovery preserves resources and is a reported limitation, not permission to clean up.

| File | Purpose |
|---|---|
| informe.md | User report from the canonical final record |
| review.json | Complete version-bound final record |
| cierre.json | Run/skill version, scope, repository/root, original harness and canonical identity/source, previous run, executor isolation/inputs/dependencies, registered temporary paths, hashes and observed closure |
| trazabilidad.jsonl | Compact observed lifecycle events and evidence references; mandatory for new runs |
| handoff.md | Historical optional transfer index, preserved without migration under [handoff.md](../reporting/handoff.md) |

Initialize cierre.json after pinning scope, before execution; register resources before use. A run without a final verdict keeps closure/trace, distinguishing interruption from completion. The default completed archive has informe.md, review.json, cierre.json and trazabilidad.jsonl plus ownership marker and selected evidence. Handoff and measurements are absent by default. New explicitly selected full/brief deliveries follow delivery.md separately from this archive; an explicit legacy handoff request uses handoff.md. Only a requested cost evaluation uses measurements.md. Preserve old archives and hashes; no migration or deletion.

Execution facts/packets remain under owned evidence/context.json, checks.json, discovery-<role>.json and verification.json. Persist selected reproductions, fixtures/configuration identity and decisive logs under archive evidence/ only when needed to reproduce/audit results. Record hashes and use retained paths in final references. A retained fixture is a copy of review evidence, not a product patch. Do not copy all scratch/history, credentials, unnecessary private metadata or dependency/build trees. Do not require workers to reload archived reports.

## Lifecycle and helper

When the interpreter/script is executable within permissions, use the helper for durable preparation, registration, retention and closure, plus its validation gates. Native preparation is not an alternative because it seems simpler or older runs used it. If the helper cannot execute, record that limitation and use native operations only when they implement and verify the same layout, ownership/closure records, exact scope, atomic writes, hashes and lifecycle. Read the contract in `scripts/review_artifacts.py`; disclose native validation rather than claiming helper execution. If guarantees cannot be verified, preserve evidence and report persistence incomplete. A helper validation failure is not unavailability and must not be bypassed with native writes.

The coordinator is the sole durable writer. Run mutations sequentially for that run. Use metadata.version from the loaded SKILL.md for --skill-version, not an older example or latest published release. Invoke through an absolute interpreter/script path and consult --help:

```text
python /absolute/skill/scripts/review_artifacts.py prepare --repo /absolute/project --scope-file /absolute/owned/session/evidence/scope.json --skill-version 2.12.0 --harness actual-harness --profile-input /absolute/owned/session/evidence/profile-selection.json --temporary-path /absolute/owned/session
python /absolute/skill/scripts/review_artifacts.py validate --run-dir /absolute/returned/run
python /absolute/skill/scripts/review_artifacts.py register --run-dir /absolute/returned/run --temporary-path /absolute/project/.worktrees/code-review-EXECUTOR --context-input /absolute/owned/session/evidence/context.json
python /absolute/skill/scripts/review_artifacts.py retain --run-dir /absolute/returned/run --input /absolute/owned/session/evidence/final-review.json --expected-schema 10 --context-input /absolute/owned/session/evidence/context.json --evidence-input /absolute/owned/worktree/tests/reproduction.cs
python /absolute/skill/scripts/review_artifacts.py validate --run-dir /absolute/returned/run --require-retained
python /absolute/skill/scripts/review_artifacts.py close --run-dir /absolute/returned/run --cleanup complete
python /absolute/skill/scripts/review_artifacts.py validate --run-dir /absolute/returned/run --require-complete
```

prepare accepts optional --output-root and --previous-run. Supply canonical scope. `register` adds resources while state is prepared or processing; `retain --temporary-path` remains compatible but does not replace registration before use. Register only exact review-owned temporary directories after checking ownership; never the user checkout, another task's workspace or the persistent archive. Registration observes paths/manifests but does not create resources, delete them or prove ownership.

`prepare` creates the trace; lifecycle helper mutations record their own events. `record-event --run-dir /absolute/returned/run --event-file /absolute/owned/event.json` records observed agent/discovery/check/grouped-verification/freshness/authorized-publication transitions; publication needs supplied authority. Archive 7 rejects manual profile events: use `select-profile` below. Summaries/reference lists are bounded. Closure stores the trace hash and {schema_version, events, last_sha256}; pending_trace preserves interrupted helper recovery. These are provenance/integrity checks, not finding truth. Consult lifecycle-trace.md and --help for the exact event contract.

`validate` is read-only: ownership/manifest integrity, repository/scope/run layout and existing selected-file hashes. For a superseded source, basic validation also accepts a structurally valid interrupted checkpoint as provisional history; it neither commits missing bytes nor certifies a final result. `--record-checkpoint` cannot mutate a superseded source. `--require-retained` additionally requires the retained final record, report, exact scope and required legacy measurements before cleanup. `--require-complete` implies retained validation and additionally requires state complete, complete/not_needed cleanup, no residuals and resources matching the retained record. Neither final gate accepts an interrupted checkpoint. Basic validation never recovers writes or adds checkpoints. `retain`, `register`, `close` and previous-run loading also reject invalid layout automatically. Gates check registered records and selected files, not arbitrary files elsewhere or finding truth. On failure, preserve the exact run/session and report the error; do not claim successful retention, cleanup readiness or closure.

New executions supply `retain --expected-schema 10`; a different schema fails before retention, independently of the declared skill version. Omission preserves legacy caller compatibility. Never downgrade a failed final record or change its run identity. `retain` verifies scope/record, writes report/final record atomically and records hashes. `--context-input` projects executors from existing context.json into closure, verifying registered paths, Git root/common repository/HEAD and pinned scope, not check outcomes or copying content. Capture it before cleanup; final schemas 8–10 require retained context even for static-only reviews, with executors=[] when no writing executors exist. Archive schema 7 binds initial profile selection, later transitions and affected assignments to the final record, trace and profile plan. Writing executors supply equivalent provenance through helper/native closure. Registered resources keep cleanup pending until observed close. Register declared residuals before retention; other native resource types need coordinator evidence. Repeatable `--evidence-input` copies selected regular files into evidence/ and hashes them; duplicate basenames or links are refused. Legacy archive/file requirements remain schema-specific. Optional measurements remain integrity-checked; only explicit `--measurement-input` or `--unavailable-reason` opts into new measurement creation. Requested evaluations supply disjoint inputs excluding inclusive parent totals; duplicate paths/known execution IDs are rejected, semantic overlap remains a coordinator check. Retry without measurement arguments preserves already retained measurements.

Legacy `retain --handoff` generates/hashes the compact handoff from the existing record/context only when that artifact is explicitly requested; new full/brief delivery uses delivery.md. Optional `--handoff-context-input` carries bounded sourced requirements/plan and pending decisions separately from executor `--context-input`; retain its references/identities through close. Preserve historical handoff files in the archive. Schema4 retention validates the trace as well as existing report/record/evidence gates. `validate --record-checkpoint` explicitly records a checkpoint in an open archive; ordinary validate remains read-only.

Select every evidence file needed to reproduce/audit the verdict or referenced by the final report, passing each via repeatable `--evidence-input`. It copies files; it neither moves them nor automatically retains context/checks/description/discussions. `--context-input` also retains the bounded context for final schemas 8–10; other required evidence still needs explicit selection. Verify retained inventory/hashes and use durable final references. Do not ask the user whether required evidence should survive disposal; retention is part of the review contract. Archive schema 7 preserves archive-6 harness metadata and adds profile/recovery lifecycle fields; schemas 1–6 retain their historical fields and file requirements.

Stop workers, retain required evidence and pass `validate --require-retained` before removing any temporary resource; with unavailable helper, record equivalent native checks. If retention/validation fails, preserve temporary evidence and report the failure. Then run the owned workspace cleanup, inspect its results and remaining resources, and supply close an observed object: {cleanup: complete|not_needed|pending, residuals: [exact absolute paths]}. Complete requires registered resources absent; not_needed requires none registered; pending identifies remaining registered resources. Inaccessible resources or modified archived files cannot be treated as successfully closed. The helper updates review.resources/report hashes with observed cleanup. Keep closure pending until that succeeds. close revalidates the complete retained-source gate before finalizing, including idempotent calls. After close, `validate --require-complete` replaces a generic completion check; report judgment, retention and cleanup separately if incomplete. Events/profile selection/registration alone cannot satisfy final retention.

After disposal, pass the observation directly with `close --cleanup complete` (or `not_needed` for no registered resources); `--cleanup pending --residual /absolute/remaining/path` lists exact remaining resources, repeating --residual as needed. This creates no post-cleanup temporary file. `--cleanup-file` remains available for an existing permitted observation file, mutually exclusive with inline flags. Native closure writes the observed object directly to durable metadata.

An interrupted run preserves initial closure and temporary manifest locations for recovery. `inspect` is read-only; `pause`, `block`, `resume`, `recover` and `restart` are separately gated and documented in [recovery.md](recovery.md). `recover` completes only the exact helper-owned pending transaction and never starts checks or agents. `restart` creates a linked run without copying old findings/results as current work. `close` is metadata finalization, not deletion. Safe recovery reads the exact run record, verifies ownership/current state and updates only that run. A successful close keeps the archive; cleanup never deletes it. Surface its actual location in the user response, outside the public MR/PR comment. With no files, retain the relevant in-conversation data and state that the durable directory was unavailable.

Completed runs are immutable; close is idempotent for their observed result. Corrections or another review create a new linked run. A post-close transfer/publication uses a separate linked operation and preserves the original archive. Initial/update/close timestamps describe recorded lifecycle observations, not guessed exact execution times or inter-agent order.

## Harness identity — resolve once at preparation

Keep `harness` exactly as received; schema 6 adds `harness_id` (canonical ID or null), `harness_catalog_version`, `harness_source: {kind, reference}` and `harness_diagnostics`. Use the local [harness catalog](harness-catalog.json); IDs are stable, not model/provider IDs. Catalog changes increment catalog_version and never reuse published IDs. Prefer the prepare helper, which resolves before creating a run. Native fallback loads this same catalog once and applies these same rules; do not rediscover identity in reviewers or after cleanup.

Resolution priority: explicit `--harness-id`, then session `CCR_HARNESS_ID`, then exact name/ID/alias (case-insensitive, ignoring outer whitespace). Declared IDs from arguments/configuration also ignore case and outer whitespace; they still must match a canonical ID, not an arbitrary display-name alias. An unknown declared ID yields null rather than silently falling back to a recognized harness name. Generic `claude-code`/`codex`/`kiro` identifies a family with unknown interface. A specific declared ID can refine a generic name of the same family; a generic ID does not erase a specific name. Unknown raw names stay literal with null ID and `unknown_harness`. Unknown requested IDs give null and `unknown_requested_id`; different families or incompatible known interfaces give null and `identity_conflict`. No fuzzy matching, provider/model inference or undocumented entrypoint detection. These diagnostics concern archive metadata, not code defects or the review verdict. Surface unknown/conflict diagnostics briefly to the user; do not rerun discovery or stop an otherwise valid review.

An empty or whitespace-only CCR_HARNESS_ID is treated as unset, so name/alias resolution applies. An explicitly supplied empty or whitespace-only --harness-id remains an input error.

Harness text and declaration references must be encodable as UTF-8. Invalid Unicode, including isolated surrogate code points in JSON, is rejected during identity validation before archive directories are created; valid Unicode references are preserved.

Optional helper arguments (not agent request flags or npx options):

```text
python <skill-path>/scripts/review_artifacts.py prepare <usual prepare arguments> --harness "Claude Code" --harness-id claude-code-desktop --harness-source-file <existing-source.json>
```

The source file must contain exactly `{ "kind": "user", "reference": "User declared Desktop for this session" }`, or kind `platform` with an actual exposed source. It requires an explicit ID. Without it the source is `argument` / `--harness-id`; configuration uses `environment` / `CCR_HARNESS_ID`; name matching uses `alias` / original name; unmatched names use `unknown` / original name. References are nonempty text up to 1024 characters; declaration provenance is not independent identity proof. Malformed source/catalog is an input error before archive creation; unknown identities and conflicts are stored diagnostics.

Configure CCR_HARNESS_ID only in the matching session/environment profile: global settings shared by Desktop and CLI can mislabel both. Prefer a session-specific explicit ID/declaration when that separation is unavailable; no extra process/counter/telemetry probes. Preserve the resolved fields through registration, events, recovery, retention and closure, bound by the existing manifest hash. Readers validate shape without consulting the installed catalog, retain historical ID/version and tolerate a different installed catalog. Never backfill or rewrite schemas 1–5 or completed runs. Future catalog versions do not retroactively identify unknown historical text. Harness identity does not change trace schema 1; the separate profile fulfillment contract uses final review schema 10, retaining schemas 8/9 behavior.

Catalog maintenance: add a stable lowercase hyphenated ID, readable name, family, interface (null for a generic family) and only unambiguous aliases; distinguish editor-specific surfaces when both may conflict. Never add model names or generic host editors such as VS Code as harness aliases. Validate collisions and generic/specific/conflict cases in test_review_harness.py. Increment catalog_version for changes after a catalog version has shipped; the initial unpublished catalog remains version 1. Unknown/custom environments need no private catalog edit to run a review: retain their raw name with null ID, then propose a catalog addition separately if a stable identity is useful. Consumers group by stored ID/version, not a reinterpretation of historical raw text.

## Schema 8–10 execution source gate

Retain supplies --context-input with the already collected neutral context; its bounded JSON is selected once as evidence/context.json. Include context.executors (empty when no writing executors), profile, selection_source (explicit/automatic, matching the final record) and profile_reference pointing to the observed profile value (normally evidence/context.json#profile). Historical schemas 8/9 use ordered {profile, reference} history entries. Archive 7/final schema 10 instead requires the exact helper-returned profile_history and execution_plan described below. Preserve existing profile milestones; do not fabricate a transition after review.

Coverage.execution links existing selected briefs/results/fallback evidence. Retention resolves only selected source bytes: JSON object-key/JSON-pointer fragments, explicit Markdown anchors/headings, or actual trace event IDs. Profile source values must match the declaration. Existing agent/started dispatch identifies the actual executor context/provider; completed discovery/grouped-verification identifies the observed actor/result. Keep unknown provider IDs null. Failed/blocked/skipped agent or interruption milestones support actual fallback sources. Shared input context does not prove independence.

Sources must exist and agree with context/trace before retention writes or cleanup; read-only validation verifies them again afterward. The initial selection precedes observed work. Later transitions can upgrade or downgrade the selected profile, but every explicit change needs user authority, observed phase and affected assignment IDs; started work cannot be relabeled or silently removed. Active obligations from the strongest applicable profile remain enforced across transitions. Prior valid discovery can be reused only when its assignment remains applicable; do not relabel completed work retrospectively. No archive-wide traversal, provider history, extra source audit file, counter probe or new worker. Missing sources block retention; portable delivery labels do not satisfy this original-source gate. New archives use schema 7, trace remains schema 1; consumers of new final results must support schema 10, including profile history and assignment selection bindings. Compatibility of the independent viewer is not presumed here.

Schema 9/10 local checks bind execution.executor to both context.executors and cierre.executors. Completed local commands require a registered executor, with matching actual head/base or pinned snapshot. Static inspection, observed CI and reused prior checks do not manufacture an executor. Retention verifies live Git provenance before cleanup; subsequent validation uses retained bindings without probing deleted worktrees. See [result-contract.md](../contracts/result-contract.md#checks).

## Archive-7 input, assignment and recovery records

Every `register --context-input` and final retention uses this context object:

```json
{
  "profile": "standard",
  "selection_source": "automatic",
  "profile_reference": "evidence/context.json#profile",
  "profile_history": [],
  "execution_plan": [],
  "executors": [],
  "review_inputs": {"scope": {}, "sources": {}, "source_set_complete": true}
}
```

This illustrates fields, not valid empty identities: copy the **exact** `profile_history` returned in `cierre.json`, including its helper-assigned IDs/events, and the pinned `scope`. `selection_source` preserves the initial selection source, while `profile`/`profile_reference` identify the effective selection; later sources remain in their history rows. `execution_plan` contains the assignment rows below before dispatch; an empty list is valid only before any assignments are planned. Retention requires the full append-preserving registry and all required results. `executors` is mandatory even when empty. `review_inputs` must match the inputs captured at prepare; when not captured there, register may capture them before work starts. Re-register the refreshed context after a profile transition. See the [executable lifecycle examples](../../docs/examples/archive7-lifecycle.md).

Select a later observed decision before affected work:

```sh
python /absolute/skill/scripts/review_artifacts.py select-profile \
  --run-dir /absolute/returned/run \
  --selection-input /absolute/owned/session/evidence/selection-change.json
```

`selection-change.json` contains exactly `{profile, selection_source, reason, reference, phase, actor, authority, affected_assignments}`. `actor` is `{kind, name, provider_id}`; `provider_id` may be null. `selection_source` is `automatic` or `explicit`; every explicit decision needs nonempty user `authority`, otherwise authority may be null. Initial decisions use `phase: prepare` and no affected IDs. Transitions use `discovery`, `verification`, `report`, `retain`, `cleanup` or `close`, before retention starts. The helper assigns `id`, `changed_from` and `event_id`; callers never supply them. History has at most 32 rows. Automatic downgrade requires a new evidence-backed reason/reference; urgency, cost, capacity or absence of findings do not justify it. `affected_assignments` lists only work that may still be superseded: started/completed assignments cannot be affected or canceled. Only active required brief references can start assignment work through `record-event`.

`cierre.json.review_inputs` captures the externally verified inputs for the run: `{scope, sources, source_set_complete?, description_identity?, requirements_identity?, plan_identity?, configuration_identity?, profile?}`. Scope and source map are required. A source value is its retained reference and lowercase SHA-256; the caller may supply at most 64. Omitted `source_set_complete` means unknown; `true` with an empty map means the coordinator verified that there are no external source files. An omitted identity is unknown. Explicit `null` means the identity was checked and is not applicable. Do not fill either case from an old report or generated output.

The archive preserves `profile_history` and `assignment_registry` as append-preserving records. Each assignment row has `{id, role, independent, required, reference, selection_id, superseded_by}`. Both histories are bounded to 32 entries. `select-profile` records an observed selection before the affected work; started or completed work cannot disappear or change identity during a later transition. The final `review.json` schema 10 must retain the initial selection and bind each assignment to its selecting profile. A later downgrade cannot discard obligations already incurred.

Checkpoint transactions retain their planned/previous file hashes and an exact `staging` inventory mapping each run-relative destination to its owned staging filename and SHA-256. Recovery may use only those declared bytes. It never deletes a similarly named foreign file or treats a partially written file as committed. Checkpoint metadata is capped at 16 MiB; selected evidence has a 64 MiB aggregate cap and 64 selected files.

Resource transfers are recorded in `resource_transfers`, up to 64 rows per run and one pending transfer at a time. A transfer binds the source/successor run and owner IDs, exact session paths and claim hashes, authority, controller and transfer ID. Replaying the same request is idempotent; changing any bound value conflicts. Incoming and outgoing history both remain on a run, so A→B→C preserves the A→B record when B transfers to C. `register` after transfer verifies the existing successor claim instead of adopting it again.

Cleanup is a separate durable intent. `resource_cleanup` identifies the exact claim/session/worktrees and records pending or completed status; `cleanup_receipts` stores the resulting claim hash and IDs. Only the ownership-checked workspace cleanup can observe deletion and submit the matching receipt. A missing directory without a receipt is `missing_unknown`, not released. A completed close can be replayed only with the same observation/receipts; a different replay is rejected. These histories are bounded to 64 receipts.

Restart has a stable, source-bound intent under `.restart-intents/<source-run-id>/<request-digest>.json` plus an `active.json` ownership descriptor while it is pending. The intent reserves one exact successor path/run/owner ID and binds the profile selection, authority, controller, current inputs, selected transfer paths and current harness. An exact retry or `recover` completes that destination; it does not search by timestamp, allocate a second run ID or dispatch work. While a restart is pending, other source mutations, transfer and cleanup are rejected. Completed/legacy source archives remain byte-for-byte immutable; a new run links the source but does not copy its findings, checks or execution results as current work. See [recovery.md](recovery.md) for the invocation and decision sequence.

For schemas 1/2 without `run_id`, the local intent key is derived from the canonical source path and owner ID; returned run/review IDs stay null and the source is unchanged. The reserved allocation keeps its reservation until its manifest is written; recovery accepts only the exact reservation/owner and its declared helper staging names. No foreign data is removed. Invalid current-input sources outside `evidence/` fail before any intent is persisted. `inspect` and lookup expose a pending restart and its exact intent path. Transactional replay requires identical captured normalized inputs, independently of unknown historical freshness; a successor identifies its owning source through `recover_source`.

Explicit abandonment before successor preparation records a receipt and preserves partial allocations. A prepared successor normally requires recovery; the exception permits explicitly abandoning an exact empty successor blocked by an absent selected resource or another review's claim, with no present/releasing source claim. Missing source claims remain `missing_unknown`, never synthetically released. Archive-7 then preserves a validated optional `restart_abandonment` object with the same receipt fields as the source receipt: `{schema_version, operation_id, source_run, source_owner_id, intent_sha256, successor_run_dir, authority, controller, reason, recorded_at, receipt_sha256}`. Its operation is blocked with source `abandon-restart`, phase `prepare` and no successor; the marker makes it terminal rather than resumable. No final result is fabricated, no review history is deleted, and no foreign resource is touched. Recovery completes a recorded cancellation before assessing new work; reads direct to the source, and mutators reject the abandoned successor. See [recovery.md](recovery.md) for eligibility, read-only rejection checks, the unresolved partial-adoption limitation and the ordered receipt protocol. Availability of the historical source does not establish the successor's own integrity.
